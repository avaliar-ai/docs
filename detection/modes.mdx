When using the Avaliar SDK, you can choose between two detection modes: **local** and **cloud**. Each mode determines where detection runs, what infrastructure is required, and how results are delivered.

<Note>
  Detection modes apply to **SDK integration** only. When using the [Proxy](/proxy/overview), detection always runs on Avaliar's cloud backend.
</Note>

## Local Detection

Local detection runs the detectors inside **your** process, so prompts and answers are checked before anything leaves your infrastructure. After a traced function returns, a background thread runs the configured detectors, then posts the trace with the results to Avaliar.

### Requirements

- Avaliar's detection engine. It is **not on PyPI**: it is shared with approved customers. [Request access](https://github.com/avaliar-ai/python-sdk#local-detection); once approved you get install instructions for your environment.
- A judge model key for the engine (for example `OPENAI_API_KEY`).

Without the engine, the SDK warns once and sends traces without local results.

### How it works

1. Your traced function executes and returns a result to the caller
2. A background thread picks up the prompt and response
3. The detection engine runs the detectors in your process
4. The trace, including detection results, is posted to Avaliar

### Pros and cons

**Pros:**
- Content is checked before it leaves your infrastructure
- No Pro plan needed for detection

**Cons:**
- Access is by request
- Uses your compute and your judge model key
- You update the engine yourself

### Best for

Development, testing, and environments where data cannot leave your infrastructure.

### Example

```python
from avaliar import traceable
from avaliar.detectors import DetectorType

@traceable(
    "llm",
    detection=True,
    detectors=[DetectorType.TOXICITY, DetectorType.PII_LEAK],
    detection_mode="local",
)
def summarize(text: str) -> str:
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "user", "content": f"Summarize: {text}"}
        ]
    )
    return response.choices[0].message.content
```

## Cloud Detection

Cloud detection offloads all analysis to Avaliar's backend infrastructure. The trace is posted immediately after the function returns, and a background worker on Avaliar's servers runs detection asynchronously via a Redis queue.

### Requirements

- A **Pro** plan
- An Avaliar API key with SDK scope (already required for tracing)

### How it works

1. Your traced function executes and returns a result to the caller
2. The trace data (prompt + response) is posted to Avaliar immediately
3. Avaliar queues the detection job for asynchronous processing
4. A backend worker picks up the job, runs all detectors, and stores the results

### Pros and cons

**Pros:**
- No additional API keys needed
- No local compute overhead
- Always uses the latest detector versions automatically
- Simplest setup

**Cons:**
- Content is sent to Avaliar's backend for analysis
- Detection results are not immediately available (async processing)

### Best for

Production deployments where you want minimal infrastructure overhead.

### Example

```python
from avaliar import traceable
from avaliar.detectors import DetectorType

@traceable(
    "llm",
    detection=True,
    detectors=[DetectorType.TOXICITY, DetectorType.PII_LEAK],
    detection_mode="cloud",
)
def summarize(text: str) -> str:
    response = client.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "user", "content": f"Summarize: {text}"}
        ]
    )
    return response.choices[0].message.content
```

## Comparison

| | Local | Cloud |
|---|---|---|
| **Data location** | Your infrastructure | Avaliar backend |
| **Extra dependencies** | Detection engine (on request), judge model key | None |
| **Compute cost** | Your resources | Included in Avaliar plan |
| **Detector updates** | You update the engine | Automatic |
| **Setup complexity** | Medium | Low |
| **Recommended for** | Data that must stay in your environment | Most production apps |

<Tip>
  Start with **local** mode during development for fast feedback, then switch to **cloud** in production to minimize overhead on your application.
</Tip>
