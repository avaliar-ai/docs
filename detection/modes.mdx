Detection runs in one of two places, depending on how you integrate.

## In your process: the Python SDK

The open-source [Python SDK](/sdk/installation) is a runtime guard that checks inside your app, before anything reaches your model or a tool runs.

- **Tiers:** rules (about a millisecond), local ONNX models on CPU with the `[local]` extra, and an optional [deep check](/sdk/deep-check) for the uncertain cases, either on your machine (Clef-Flash) or through an API you choose.
- **Decisions:** your policy file (`avaliar.yaml`) says what to allow, warn about, redact, block or send for approval, at five checkpoints: input, output, tool call, tool result and action.
- **Evidence:** every decision is written to a hash-chained local log.
- **Data:** nothing leaves your machine unless you configure an API deep check or set `AVALIAR_API_KEY`. See [What leaves your machine](/sdk/network).
- **Plan:** none needed. With an `sdk` key the decisions also appear on the dashboard; see [Connecting to Avaliar Cloud](/sdk/cloud).

```python
from avaliar import Guard

guard = Guard()
d = guard.check_input(user_message)
if d.blocked:
    return d.reply
```

## On Avaliar's backend: Proxy and OpenTelemetry

**Proxy.** When you route LLM calls through the [Avaliar Proxy](/proxy/overview), detection always runs on Avaliar's backend. Prompt injection is checked synchronously, before the request reaches the LLM; the other detectors run asynchronously once the response is back.

**OpenTelemetry.** Traces sent over [OTLP](/otlp/overview) are scanned on Avaliar's backend when their API key was created with cloud detection. A key without it stores traces unscanned, and the platform shows them as **not scanned** rather than as clean.

Which detectors run on the backend is controlled per organization under **Settings, Security, Detectors**. See [Detector Types](/detection/detectors).

## Comparison

| | Python SDK | Proxy and OpenTelemetry |
|---|---|---|
| **Where checks run** | Your process | Avaliar's backend |
| **When** | Before the message reaches your model, before a tool runs, before the reply is shown | Prompt injection before the LLM (Proxy); the rest after the response |
| **What is checked** | Input, output, tool calls, tool results, actions | Prompts and responses |
| **Data location** | Your infrastructure, unless you choose otherwise | Avaliar's backend |
| **Setup** | `pip install` and a policy file | A URL or an OTLP endpoint and a key |
| **Recommended for** | Python apps and agents, private data, offline use | Any language, no code changes |
