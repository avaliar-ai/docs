Get your AI agent routed through the Avaliar Proxy in three steps. The only changes required are your endpoint URL and adding your Avaliar API key to the request body.

<Tip>
  Most integrations should use the **[OpenAI-Compatible Endpoint](/proxy/openai-compatible)** instead: it works with any OpenAI SDK or no-code tool by just setting a base URL and Bearer key. The per-provider endpoints on this page are a lower-level alternative (body-based keys, one path per provider).
</Tip>

<Steps>
  <Step title="Get a Proxy API Key">
    Generate an API key from the [Avaliar Dashboard](https://app.avaliar.ai/settings/api-keys).

    1. Navigate to **Settings → API Keys**
    2. Click **Create API Key**
    3. Select the **Proxy** scope
    4. Copy the generated key: you won't be able to see it again

    <Warning>
      Never expose your Avaliar API key in client-side or browser-based code. Use it only in server-side applications or backend AI agent services.
    </Warning>
  </Step>

  <Step title="Update Your Endpoint URL">
    Replace your LLM provider's endpoint URL with the corresponding Avaliar Proxy URL, and add your `api_key` to the request body.

    The proxy has a dedicated endpoint per provider:

    | Provider | Proxy Endpoint |
    | -------- | -------------- |
    | OpenAI | `POST https://proxy-api-ckjd.onrender.com/api/openai_service/chat_completion` |
    | Anthropic | `POST https://proxy-api-ckjd.onrender.com/api/anthropic_service/chat_completion` |
    | Google Gemini | `POST https://proxy-api-ckjd.onrender.com/api/gemini_service/chat_completion` |

    Your existing provider API key (OpenAI key, Anthropic key, etc.) stays in the request body exactly where it was. Just add `api_key` alongside it.

    <CodeGroup>
      ```python OpenAI
      import requests

      response = requests.post(
          "https://proxy-api-ckjd.onrender.com/api/openai_service/chat_completion",
          json={
              "api_key": "your-avaliar-api-key",        # Avaliar key (new)
              "openai_api_key": "your-openai-key",       # Your existing OpenAI key
              "model": "gpt-4o",
              "messages": [
                  {"role": "user", "content": "Hello!"}
              ]
          }
      )
      ```

      ```python Anthropic
      import requests

      response = requests.post(
          "https://proxy-api-ckjd.onrender.com/api/anthropic_service/chat_completion",
          json={
              "api_key": "your-avaliar-api-key",         # Avaliar key (new)
              "anthropic_api_key": "your-anthropic-key", # Your existing Anthropic key
              "model": "claude-sonnet-4-5",
              "messages": [
                  {"role": "user", "content": "Hello!"}
              ],
              "max_tokens": 1024
          }
      )
      ```

      ```python Gemini
      import requests

      response = requests.post(
          "https://proxy-api-ckjd.onrender.com/api/gemini_service/chat_completion",
          json={
              "api_key": "your-avaliar-api-key",       # Avaliar key (new)
              "gemini_api_key": "your-gemini-key",      # Your existing Gemini key
              "model": "gemini-2.5-flash",
              "messages": [
                  {"role": "user", "content": "Hello!"}
              ]
          }
      )
      ```


    </CodeGroup>

    <Info>
      If you omit your provider API key (e.g. `openai_api_key`), the proxy will use a server-side key. Contact support to confirm whether this is enabled for your plan.
    </Info>
  </Step>

  <Step title="View Traces in the Dashboard">
    Open the [Avaliar Dashboard](https://app.avaliar.ai/traces) to see your traces appear in real time.

    Each trace includes:
    - Full prompt and response content
    - Provider, model, and token counts
    - End-to-end latency and proxy overhead
    - Safety detection results and any identified issues
    - Cost estimates

    <Tip>
      Make a single test request after setup and check the [Traces](https://app.avaliar.ai/traces) page. A trace should appear within a few seconds.
    </Tip>
  </Step>

## Request Parameters

All proxy endpoints accept the same parameters as the underlying LLM provider, plus a few Avaliar-specific ones.

### Avaliar-Specific Parameters

| Parameter | Type | Required | Description |
| --------- | ---- | -------- | ----------- |
| `api_key` | string | Yes | Your Avaliar API key, generated from the dashboard |
| `is_confidential` | boolean | No | If `true`, the prompt and response are **not** stored in traces. Defaults to `false` |

### Provider API Key Parameters

| Parameter | Provider | Description |
| --------- | -------- | ----------- |
| `openai_api_key` | OpenAI | Your OpenAI API key. If omitted, the proxy uses a server-side key |
| `anthropic_api_key` | Anthropic | Your Anthropic API key. If omitted, the proxy uses a server-side key |
| `gemini_api_key` | Gemini | Your Google Gemini API key. If omitted, the proxy uses a server-side key |

All other parameters (model, messages, temperature, max_tokens, etc.) are passed through to the provider unchanged. See the [Supported Models](/proxy/models) page for available model IDs.

---

## Confidential Requests

If a request contains sensitive information that should not be stored, set `is_confidential: true`. The proxy will still forward the request to the LLM provider and count it in your usage metrics, but the prompt and response content will not be saved to Avaliar.

```python
requests.post(
    "https://proxy-api-ckjd.onrender.com/api/openai_service/chat_completion",
    json={
        "api_key": "your-avaliar-api-key",
        "model": "gpt-4o",
        "messages": [{"role": "user", "content": "Sensitive content here"}],
        "is_confidential": True   # Prompt and response are not stored
    }
)
```

<Note>
  Detection does not run on confidential requests. Token counts and latency are still tracked.
</Note>

## Error Handling

If the proxy rejects a request, it returns a JSON error response:

```json
{
  "is_successful": false,
  "message": "Invalid or revoked API key"
}
```

Common error codes:

| Status | Cause |
| ------ | ----- |
| `401` | Invalid, expired, or revoked Avaliar API key |
| `400` | Missing required parameters or invalid request body |
| `422` | Request body failed schema validation |
| `403` | Request blocked: prompt injection detected |
| `500` | Internal error or LLM provider failure |

If a request is blocked due to prompt injection, the response will indicate the block reason. The blocked request is still recorded as a trace on the Avaliar platform.
