The Avaliar Python SDK is an open-source runtime guard. It runs inside your process and, at every risky point of your app or agent, it does three things:

1. **Checks** the text, tool call or action: rules, local models, and an optional deep check for the uncertain cases.
2. **Decides** by a policy file your team owns (`avaliar.yaml`).
3. **Records** every decision in a tamper-evident local log you can verify.

It works fully offline with no account. Without an API key it makes no network calls to Avaliar.

## Requirements

Python **3.11** or newer (3.14 is supported).

## Install

```bash
pip install avaliar-python-sdk
```

The package installs as `avaliar-python-sdk`; you import it as `avaliar` and run it as the `avaliar` command.

The base install gives you the rules (tier 0), the policy file, the evidence log and the CLI. It depends only on `pydantic`, `orjson`, `pyyaml` and `requests`, and `import avaliar` loads none of them until you use them.

## Extras

| Extra | Install | Adds |
|---|---|---|
| `local` | `pip install "avaliar-python-sdk[local]"` | Local ONNX models on CPU (tier 1): prompt injection and toxicity, plus jailbreak, names and addresses, off topic and groundedness models fetched with `avaliar models pull` |
| `otel` | `pip install "avaliar-python-sdk[otel]"` | An OpenTelemetry span for every check and for every `@traceable` function. See [OpenTelemetry](/sdk/opentelemetry). |
| `openai-agents` | `pip install "avaliar-python-sdk[openai-agents]"` | `protect()` and `run()` for the OpenAI Agents SDK |
| `langchain` | `pip install "avaliar-python-sdk[langchain]"` | `AvaliarMiddleware` for LangChain 1.x agents |
| `mcp` | `pip install "avaliar-python-sdk[mcp]"` | `GuardedSession` for MCP clients |

Extras combine: `pip install "avaliar-python-sdk[local,otel,langchain]"`.

<Note>
  Nothing downloads at runtime. Model files come with the `[local]` extra or from an explicit `avaliar models pull`, and are checked against pinned sha256 hashes. The local deep check (Clef-Flash, 5.4 GB) is fetched only when you ask for it by name.
</Note>

## Check the install

```bash
avaliar --version
avaliar doctor
```

`avaliar doctor` checks the Python version, the policy, the local models, the deep check, the evidence log and the machine, and tells you what is missing. See the [Quickstart](/sdk/quickstart) for the full first run.

## Environment variables

None are required. These change where the SDK looks or what it does:

| Variable | Default | What it does |
|---|---|---|
| `AVALIAR_POLICY` | `./avaliar.yaml` | Path to the policy file when `Guard()` is given none |
| `AVALIAR_HOME` | the policy file's folder | Base folder for evidence paths and the per-install secret |
| `AVALIAR_APP` | none | App name written on every evidence record (`app:` in the policy wins) |
| `AVALIAR_MODELS_DIR` | none | Extra folder to look for local model files in |
| `AVALIAR_ONNX_THREADS` | `2` | Threads per local model |
| `AVALIAR_LLAMA_SERVER` | the pinned install, then `PATH` | The `llama-server` binary for the local deep check |
| `AVALIAR_API_KEY` | none | Links the SDK to Avaliar Cloud. See [Connecting to Avaliar Cloud](/sdk/cloud). |
| `AVALIAR_API_URL` | `https://api.avaliar.ai/api/v1` | Avaliar Cloud address, used only when `AVALIAR_API_KEY` is set |
| `AVALIAR_TIMEOUT` | `10` | Seconds to wait for Avaliar Cloud |
| `AVALIAR_NO_TIPS` | off | Hide the tips the CLI prints |

Deep check providers read their own key variables (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY` and so on). See [Deep check](/sdk/deep-check).

## Logging

The SDK logs to the `avaliar` logger. It warns once about problems that need you (a policy warning, evidence that cannot be written, a deep check that is unreachable) and never raises from a check. `avaliar -v <command>` prints SDK activity on the command line.

```python
import logging
logging.getLogger("avaliar").setLevel(logging.INFO)
```
