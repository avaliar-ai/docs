The SDK is open source. This page covers a local development setup, the project's rules and where things live.

**Repository:** [github.com/avaliar-ai/python-sdk](https://github.com/avaliar-ai/python-sdk)

## Set up

You need Python 3.11 or newer, Git and [`uv`](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/avaliar-ai/python-sdk.git
cd python-sdk
uv sync --extra local --extra otel
```

## Commands

```bash
uv run pytest                                   # no network, no keys needed
uv run --python 3.11 pytest                     # the lowest supported version
uv run ruff check --no-fix avaliar tests scripts
uv run mypy avaliar
uv run python scripts/accuracy.py --misses      # tier 0 and 1 accuracy on the labelled set
uv run python -m avaliar.policy.schema > schema/policy.v1.json   # after schema changes
uv run python scripts/checkpoint_pages.py       # checkpoint reference pages, after category or preset changes
uv run python models/fetch.py                   # local model files
```

Tier 1 tests and accuracy runs need the model files: run `models/fetch.py`, then set `AVALIAR_MODELS_DIR=$PWD/models/avaliar_local_models`.

## Rules

- **No phone-home.** Without `AVALIAR_API_KEY` the SDK makes no network calls to Avaliar. Nothing downloads at runtime. Every new network call goes in `docs/network.md` (see [What leaves your machine](/sdk/network)).
- **Never silently clean.** A category that could not be scored is `not_evaluated` with a reason, never a pass.
- **Never break the app.** Checks return a `Decision`. Only `AvaliarPolicyError` (at construction) and the opt-in `GuardBlocked` and `GuardUnavailable` are raised. Detector and deep check faults are caught and recorded.
- **Python 3.11+.** No syntax that needs 3.12.
- **A small base install.** `pydantic`, `orjson`, `pyyaml`, `requests`, `typing-extensions`. `import avaliar` loads none of them and stays under 150 ms; heavy imports happen inside functions.
- **Categories are defined in one place** (`avaliar/categories.py`). A new category also needs a deep check question if it is judgeable, documentation, and reviewed labelled cases.
- **The labelled set** only takes cases that passed a second review, from public data with a redistributable licence, and never data a local model was trained on.
- No em dashes in code, comments or docs.

## Layout

| Path | What |
|---|---|
| `avaliar/guard.py` | `Guard`, the checks, redaction, evidence records, approval |
| `avaliar/engine/` | Tiers, bands, budgets, the deep check call, rules, per-session memory |
| `avaliar/policy/` | Schema, loader (`extends`, merge, example files, hash, line numbers), presets |
| `avaliar/examples.py` | Your own examples: normalising, matching, example files |
| `avaliar/detectors/rules/` | Tier 0, one module per rule detector |
| `avaliar/detectors/local/` | Tier 1, one module per local model (ONNX) |
| `avaliar/judges/` | Tier 2: decision models (Clef-Flash, Jev), LLM APIs, Avaliar Cloud |
| `avaliar/evidence/` | Records, the hash-chained writer, `verify` |
| `avaliar/cli/` | The `avaliar` command |
| `avaliar/setup/` | `avaliar setup` and `avaliar init` |
| `avaliar/integrations/` | OpenAI Agents SDK, LangChain, MCP |
| `avaliar/redteam/` | The red-team runner and the bundled pack |
| `avaliar/trace.py`, `avaliar/telemetry/` | `@traceable` and OpenTelemetry output |
| `avaliar/cloud/` | The Avaliar Cloud client and the evidence uploader |
| `tests/labelled/` | The open labelled set, its sources, and the accuracy baseline |
